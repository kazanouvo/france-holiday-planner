# France Holiday Planner — Hermes Agent Rules

Skills applied from empire-repos: superpowers, ponytail, i-have-adhd, caveman, last30days-skill, diagram-design.

## Workflow (superpowers)
- Brainstorm before code: read the task fully, trace the real flow end-to-end, then pick the smallest change.
- TDD: write tests first, then code, then refactor.
- Verification before completion: run the narrowest relevant tests, then build, then smoke checks.
- Never weaken/skip/delete tests to make them pass.
- Review the diff before handoff; report skipped checks and blockers honestly.

## Output Style (ponytail + i-have-adhd)
- Lazy senior dev: reuse existing code/deps/std-lib before writing. No new dependency without concrete reason.
- Boring over clever. Shortest working diff wins.
- ADHD-friendly: lead with the answer, keep explanations short, use bullet lists and tables.
- No abstractions that weren't explicitly requested.

## Code Style (caveman)
- Terse, direct. No filler words. No "Let me..." prefixes.
- One sentence per thought. Short answers.

## Research (last30days-skill)
- Before implementing a feature or fixing a bug, research the topic across Reddit, X, YouTube, HN, and the web.
- Synthesize a grounded summary; cite sources.

## Diagrams (diagram-design)
- Use self-contained HTML + SVG for architecture/flow diagrams. No Mermaid slop.
- Editorial style: clean lines, no shadows, no gradients.

## Repository Workflow
- Normal development targets `development`. Never commit directly to `main`.
- Create `feature/*` or `fix/*` branches from `development`.
- Integrate through review: feature/fix branch -> `development` -> `main`.
- Do not merge or promote to `main` until relevant checks pass.

## Engineering Rules
- Use the target app's actual dependencies and conventions; do not assume every app has the same stack.
- Do not add a dependency without a concrete reason and documentation in the change.
- Keep changes focused and avoid unrelated generated-file churn.
- Never expose secrets, API keys, credentials, tokens, private keys, or populated `.env` files.
- Record significant cross-app, data, deployment, or public-interface decisions in `DECISIONS.md`.

## Validation
- Run the narrowest relevant app-local tests first.
- Then run available frontend lint/type-check/build and backend lint/type-check commands.
- Before handoff, review the diff and report commands run, failures, and skipped checks.
